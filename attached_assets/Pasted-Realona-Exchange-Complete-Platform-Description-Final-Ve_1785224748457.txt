1. CANCEL TRADE FEATURE

Backend Logic

· A trade can only be cancelled if its status is "pending" (payment not yet made)
· When cancelled:
  · Trade status changes to "cancelled"
  · Account listing becomes available again for other buyers
  · System message appears in chat: "Trade cancelled"
  · No money moves because payment was never confirmed

Frontend Interface

· "Cancel Trade" button on Trade Details page
· Button only appears when trade status is "pending"
· Clicking triggers pop-up: "Are you sure you want to cancel this trade?"
· On confirmation: trade cancels → user returns to marketplace

Who Can Cancel

· Both buyer and seller can cancel (as long as payment hasn't been confirmed)
· Once payment is made → cancellation is disabled (protects both parties)

After Cancellation

· Buyer loses no money (payment wasn't made)
· Seller's account returns to "Available" status
· Both users receive system notification in chat
· Trade appears in history as "cancelled"

3. OTP/ACCESS CODE SYSTEM – FULL ESCROW FLOW

A. When Seller Lists an Account

Important: eFootball accounts use Konami ID, so the form should reflect this.

Field Purpose
Konami ID The email/username used to log in to eFootball
Konami Password The password for the Konami account
Access Code / OTP The code needed to access the account
Recovery Email Email linked to the account for password reset

Form Fields:

· Add new field on "Sell Account" form:
  · "Konami ID" (email/username, hidden from public)
  · "Konami Password" (password field, hidden from public)
  · "Access Code / OTP" (password field, hidden from public)
· Code is stored securely in the database
· Never shown to buyers until payment is confirmed
· Seller enters all details the buyer will need to access the account

B. After Buyer Pays (Payment Confirmed)

· System message appears in chat:
  "Payment confirmed. Seller can now share the access code with the buyer."
· Seller manually sends Konami ID, Password, and OTP/code to buyer via chat
· Information is only visible to:
  · Buyer
  · Seller
  · Admin (for dispute resolution)

C. Buyer Receives Code and Logs In (First OTP)

1. Buyer receives Konami ID and Password from seller
2. Buyer logs into the eFootball account via Konami
3. System asks for OTP code (sent to seller's email or provided by seller)
4. Buyer requests OTP from seller
5. Seller sends first OTP via chat
6. Buyer enters OTP and gains full access

D. Buyer Changes Email – REQUIRES SECOND OTP

· After buyer successfully logs in with first OTP:
  · Instructions appear:
    "Please change the email address to your own immediately to prevent the seller from logging in again."
· Buyer proceeds to change the email address
· CRITICAL STEP: When buyer attempts to change the email:
  · The system requests a new OTP code
  · Buyer must request the new OTP from the seller
  · Seller sends the second OTP via chat
  · Buyer enters the second OTP to confirm the email change
· Once the second OTP is verified:
  · The email address is successfully changed to the buyer's email
  · The seller can no longer access the account

E. Buyer Confirms Access – Final Step

· After email is successfully changed and buyer has full control:
  · Buyer clicks new button: "I Have Accessed the Account"

F. Funds Released to Seller

· After buyer confirms access:
  · Trade status changes to "completed"
  · Funds released to seller (minus platform fee)
· Seller receives their money
· Trade is marked complete

G. Dispute Handling (If Code Doesn't Work)

· Buyer can report the seller
· Admin can:
  · View the code in chat
  · Test the code themselves
  · Decide who to refund or pay
· Admin can reverse the transaction if needed

11. MAKE AN OFFER FEATURE

Purpose

· Allow buyers to negotiate price before paying
· Create more flexible trading experience

How It Works

Buyer Side:

1. Buyer clicks "Make Offer" on account listing
2. Enter proposed price (must be lower than listed price)
3. Add optional message to seller (e.g., "I can pay immediately")
4. Offer is sent to seller

Seller Side:

1. Seller receives notification of new offer
2. Seller can:
   · Accept offer → Trade initiates at offered price
   · Reject offer → Offer is declined, user can make new offer
   · Counter offer → Seller proposes another price

Offer Rules:

· Offer is not binding until seller accepts
· Buyer cannot pay until offer is accepted
· Multiple offers can be made (one at a time)
· Offer expires after 24 hours
